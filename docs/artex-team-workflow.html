보안 DB 실험: 시작 권한을 분리한다

두 제품에 같은 합성 데이터와 평문 대조군을 사용합니다. 아래는 검증 질문이며 제품의 보호 효과를 미리 단정한 표가 아닙니다.

시나리오제공하는 접근주요 검증 질문기록해야 할 조건
A · 저장 파일 유출DB 파일·백업의 복제본. 키 제외 실험과 키 포함 실험은 별도.합성 평문 표식, 구조, 메타데이터 중 무엇을 복구할 수 있는가?파일 범위, 백업·로그 포함 여부, 키 저장 위치, 정상 데이터 존재 대조군
B · DB 관리자DB 관리 계정. OS·애플리케이션·KMS 권한은 별도 명시.조회 결과와 카탈로그·로그에서 어떤 정보가 보이는가?실제 계정 권한, 클라이언트 복호화 유무, 쿼리 종류와 관측 가능한 정보
C · DB 호스트 장악정의된 OS 권한. 앱 호스트·KMS 접근은 자동 포함하지 않음.해당 호스트의 파일·프로세스 메모리에서 평문이나 키 관련 정보가 관측되는가?프로세스, 데이터 처리 시점, 키 접근 경로, 컨테이너 경계, 수집 도구 권한
D · 애플리케이션 호스트 (선택)복호화 클라이언트가 동작하는 호스트. C와 독립 실행.클라이언트가 처리하는 평문과 DB 서버가 보는 정보는 어떻게 다른가?드라이버·키 서비스·자격 증명 경계, 동일 쿼리의 서버/클라이언트 관찰

호스트 접근을 미리 제공하는 실험은 assumed-breach 평가입니다. 실제 초기 접근 성공을 증명한 것으로 보고하지 않습니다.

팀이 지켜야 하는 실행 규칙

증거로 연결

공유 저장소에 작업 ID, 시나리오·권한, 명령과 종료 코드, 시간, 원본 경로·해시, 관찰과 결론을 저장합니다. 각 에이전트에는 관련 자료만 전달합니다.

검토를 통과해야 완료

통과 / 보충 필요 / 판단 불가를 구조화합니다. 핵심 결론은 독립 재현과 대조 실험을 확인합니다. 모델 다수결만으로 완료 처리하지 않습니다.

실패 종류별 처리

한도·네트워크 대기는 평가 실패와 분리합니다. 재시작 전 실행 결과를 확인하며, 실행 여부가 불명확한 변경 작업은 자동 반복하지 않습니다. 시간·비용·반복 예산을 함께 둡니다.

이 문서는 워크플로 설계 시각화입니다. ARTEX의 실행 설정을 변경하거나 작업을 시작하지 않습니다. 모델 배치는 제안이며 성능 보장이 아닙니다.
평가 과정 참고: NIST SP 800-115 · 탐지와 방어 평가 참고: CISA Red Team Assessment. 에이전트 배치와 DB 실험 매트릭스는 이 프로젝트를 위한 설계 제안입니다.
