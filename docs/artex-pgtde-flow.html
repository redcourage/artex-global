Heracles Local / MVP와의 핵심 차이

pg_tde

인덱스와 테이블을 읽으면 엔진이 평문을 사용합니다. 암호화는 SQL 사용법을 거의 바꾸지 않는 대신, 정상 DB 접근자를 데이터에서 분리하는 장치는 아닙니다.

Heracles Local

검색은 FHE 인덱스 계산과 검색 결과 판정을 거칩니다. AES로 감싼 원본 컬럼은 별도 복호화 경로입니다. 다만 FHE 비밀키·AES 키가 같은 DB 호스트에 있는 Local 구성입니다.

비교에서 볼 것

검색만 할 때 원본 컬럼 평문이 어디에 나타나는가? 값을 조회하면 어떻게 달라지는가? 호스트 권한으로 키를 사용할 수 있는가? 세 질문을 분리합니다.

독립 실행 구성

시험: Percona DB + pg_tde
→
동일 호스트의 keyring
→
외부 SaaS 없이 실행

키를 분리한 대조군은 자체 호스팅 OpenBao 같은 provider를 추가할 수 있습니다. 이 경우도 외부 SaaS는 필요 없지만 별도 서비스가 하나 늘어납니다. 키 배치가 다른 결과를 암호 방식만의 우열로 해석하지 않습니다.

pg_tde 라이선스키 provider·로컬 시험 구성
논의용 개념도 · 2026-10-19 공식 문서 확인 · 실제 DB를 실행한 결과가 아닙니다. 암호문·토큰 표기는 설명용이며 제품의 바이트 형식을 재현하지 않습니다.
