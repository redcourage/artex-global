# Codex bridge 외부 리뷰 검증

2026-10-16. 사용자가 전달한 Claude 리뷰를 코드 및 독립적인 가짜 App Server로
재검증했다. 실제 추론을 추가로 실행하거나 계정 토큰을 읽지 않았다.
초기 기능 probe는 Go 변경 없이 성공했다. 이후 사용자가 승인한 사용량·비용
기능은 Go의 사용량 수집·저장 경로를 확장하므로 그 구분을 유지한다.

아래 표와 복구 권고는 **수정 전 조사 결과**다. 이후 사용자가 전부 수정을
요청하여 보완했으며 현재 상태는 문서 마지막의 수정 기록에 정리했다.

| 항목 | 판정 | 실제 영향 |
|---|---|---|
| 오류 한 번이면 Worker 영구 사망 | 표현 수정 필요, 복구 결함 확인 | Worker pool 루프는 살아 있다. 세션 삭제 뒤 기존 assistant 이력을 거부해 같은 intent의 재시도가 실패하고 최종 `blocked`가 된다. |
| 모든 예외가 세션 삭제 | 일부만 해당 | 추론 처리 try 내부의 오류는 삭제한다. 입력 검증 등 그 이전 오류는 삭제하지 않는다. |
| stdout 비JSON 줄이 전체 reader 종료 | 재현 | 후속 정상 줄도 읽지 않으며, 자식이 살아 있어도 모든 연결 세션이 disconnected가 된다. |
| health가 장애를 숨김 | 재현 | reader 종료 상태에서도 HTTP health가 200을 반환한다. |
| 프롬프트가 로컬 Codex 기록에 보존 | 확인 | `ephemeral: false`; 실제 probe thread의 rollout이 존재한다. 외부 유출을 확인한 것은 아니다. |
| 토큰 미반환 | 초기 버전에서 사실 | 현재 작업에서 이벤트→응답→ARTEX 원장 연결을 추가했다. |
| 테스트 공백 | 단위 테스트 기준 사실 | 전체 도구 왕복·planner reset은 실제 E2E에서 실행됐다. 카탈로그 변경·미등록 도구·병렬 결과 순서 등은 더 정밀한 회귀 테스트가 필요하다. |
| 도구 이전 텍스트 지연 | 재현 | 도구 응답 내용은 빈 문자열, 최종 응답에는 앞뒤 설명이 이어 붙는다. 중도 실패하면 누적 텍스트가 전달되지 않는다. |
| 세션·lock 누적 | 재현 | 완료 키 50개 후 state/lock/AppServer session 각 50개. abort로 state를 지워도 lock 50개가 남는다. |
| 모델명이 계정 종속 | 해당 | 러너의 두 모델은 기본값이며 인자로 변경 가능하다. 계정별 실제 가용성을 보장하지 않는다. |

사용량 작업 중 추가한 회귀 테스트는 기본 도구 결과 왕복과 turn 종료 시 집계,
후속 turn의 사용량 미보고, 오류 응답의 보고된 사용량 보존을 검사한다.
현재 Python 테스트는 러너 정리 테스트를 포함해 20개다. 이것으로 카탈로그 변경,
미등록 도구, 병렬 도구 결과 순서 등 기존 프로토콜 테스트 공백이 모두 해소된 것은 아니다.

## 복구 권고

400을 무조건 503으로 바꾸는 것으로 해결되지 않는다. Norma의 연결 재시도는
408/429/5xx를 취급하지만 ARTEX 엔진 자체도 model_error intent를 재시도한다.
이미 실행한 도구의 ID·결과 전달 여부·응답 캐시를 보존하지 않고 전체 이력을
새 모델에 재실행시키면 작업을 중복 제안하거나 부작용을 반복할 수 있다.

우선 reader 생존 상태를 추적하고 장애 시 health와 신규 요청을 unavailable로
만들어야 한다. 다음으로 입력 오류·일시적 추론 오류·복구 불가 상태를 구분하고,
도구 ID와 전달 상태를 보존하는 재개 방식을 설계해야 한다. 비JSON 줄을 무조건
무시하는 것도 도구 호출 유실을 가릴 수 있으므로 복구 가능성을 확인해야 한다.

설치된 CLI 스키마는 `ephemeral: true`를 지원한다. 현재 bridge가 재시작 복원을
지원하지 않는다는 점에서 임시 thread가 적합한 기본값 후보지만, 이는 ARTEX DB,
별도 로그, 실험 산출물까지 제거하는 설정은 아니다. 이번 요청은 문제 조사이므로
보존 모드·오류 재생 정책을 임의로 변경하지 않았다.

## 인증·정책 주장

[공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)는 자기 제품에
Codex를 통합하는 용도로 App Server를 안내한다.
[공식 인증 문서](https://learn.chatgpt.com/docs/auth)는 ChatGPT 구독 로그인과
API 키 로그인을 구분하며, CI/CD 같은 프로그램 방식 작업에는 API 키를 안내한다.
따라서 이 연결만으로 “인증 우회”, “제재 대상”이라고 단정할 근거는 확인하지 못했다.
동시에 이 문서 확인만으로 특정 운영 방식의 약관 적합성을 보증할 수도 없다.
전달된 리뷰의 과거 차단 사례는 출처가 없어 이번 조사로 확인할 수 없었다.
실험적 프로토콜의 버전 호환성과 계정별 한도는 별도 운영 제약이다.

## 사용자 승인 후 수정 기록

- `app_server.py`: 줄 단위 파싱 오류 격리, EOF·I/O·RPC 타임아웃 시 unhealthy
  전환, 동시 요청 간 단일 프로세스 재시작, 종료 대기→terminate→kill의 유한 정리.
  일시 서버·연결 오류와 인증·정책·한도 오류를 Codex 오류 코드로 구분한다.
- `bridge.py`: health가 실제 프로세스·리더 상태를 반영한다. 400/409/503을
  구분하고 503에 Retry-After를 반환한다. 모델 목록은 로컬 인증 후에만 노출한다.
- `sessions.py`: HTTP 타임아웃은 실행을 폐기하지 않는다. 동일 요청은 진행 중인
  작업 또는 캐시된 응답을 재사용한다. 실패 후 ARTEX 이력으로 새 임시 thread를
  만들고, 완료된 도구 결과를 복구 문맥에 제공한다. 불확실한 결과는 409로 거절한다.
- 모든 새 thread는 `ephemeral: true`. 과거 rollout은 삭제하지 않았다.
- 기본 256세션, 유휴/방치 1800초 정리, 마지막 요청이 떠난 lock 즉시 회수.
  동시 퇴거 중 용량 예약과 오래된 정리 작업이 새 세션을 삭제하는 경합도 수정했다.
- 도구 앞 텍스트는 해당 도구 응답에 포함하고, 뒤 텍스트와 별도 assistant item은
  경계를 유지한다. 미등록·중복·과도한 도구 요청을 거절하고 병렬 결과를 ID로 대응한다.
- 러너의 기본 모델은 계정 목록에서 선택한다. 명시 모델이 없으면 조기에 실패하며,
  가격표에 없는 모델도 비용 미계산 상태를 올바르게 검증한다.
- 타임아웃 후 늦게 실패한 추론의 사용량을 다음 응답까지 보존한다. 알려진 추론과
  사용량 미보고 시도(`missing_ids`)를 별도로 기록하고 재시도 중 중복 삽입을 막는다.

복구 결과 재사용은 현재 사용자 턴의 복구 구간에만 적용한다. 새 사용자 턴이나
새 도구 작업 이후에는 과거 읽기 결과를 새로운 관측처럼 재사용하지 않는다.
단, 이름·인자만으로 의도적 반복을 완벽히 식별할 수 없고, ARTEX 자체가 잃어버린
외부 도구 결과를 생성할 수도 없다. 따라서 일반적인 exactly-once 실행이나
수시간 무중단 운영을 인증하는 변경은 아니다.

검증: Python 회귀 테스트 66개, 전체 Go 테스트 및 사용량 경로 race 테스트 통과.
정상 실제 ARTEX 작업은 90.66초에 12/12 검사 통과했고, 생성 thread 8개와 일치하는
Codex rollout 파일은 없었다. 첫 장애 주입 실행은 워커의 WebFetch 결과 전달 직후
해당 실험이 소유한 Codex 자식만 SIGTERM으로 종료했다. 자동 재시작 후 92.24초에
12/12 검사 통과, fixture 조회 정확히 2건, activity 오류 0건이었다.
후속 코드 리뷰의 경합·부분 사용량 수정까지 포함한 최종 장애 주입 실행은
90.71초에 작업 완료, fixture 조회 2건, activity 오류 0건, 보고된 토큰의 DB 합계
일치를 확인했다. 생성 thread 10개에 대응하는 rollout 파일은 없었다.

최종 실행에서는 강제 종료 시 사용량을 보고하지 못한 시도 1건이 별도 미확정
행으로 남았다(전체 26행 중 가격 계산 가능 25행). 기존 러너는 누락 0건만 허용해
처음 11/12로 종료했다. 검사기를 “미보고 행에는 비용이 없고 모델별 누락 건수가
원장과 일치하는가”로 수정하고, 회귀 테스트와 같은 증거의 재검증으로 12/12를
확인했다. 원본 `checks.json`과 재검증 `checks-revalidated.json`을 둘 다 보존했다.
추론 코드를 변경해 다시 돌린 것처럼 표현하지 않는다. 이것은 미보고 비용을
추측하거나 0원으로 숨기지 않는 의도된 부분 집계다.

증거는 무시되는 로컬 `test-results/codex-probe/2026-10-16-hardening/`에 보관한다.
