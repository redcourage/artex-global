TEAM / RESPONSIBILITIES

역할은 나누되, 모든 역할을 상시 실행하지 않습니다.

역할을 선택하면 입력·책임·산출물·현재 ARTEX와의 차이를 볼 수 있습니다. 모델 배치는 사용자 구상을 반영한 초안입니다.

7개 논리 역할 · 고정 인원수 아님

공유하는 것

평가 계획, 작업 상태, 검증된 사실, 증거 ID, 변경 기록. 각 에이전트는 필요한 부분을 조회합니다.

분리하는 것

에이전트 세션·권한, 실험 환경, 실행자의 주장과 검토자의 판정. 전체 대화를 매번 복제하지 않습니다.

코드가 맡는 것

범위·예산 제한, 상태 전이, 증거 저장, 실행 중복 방지, 잠금과 재개. 이 기능들은 LLM의 약속만으로 보장하지 않습니다.

EXPERIMENT / STARTING PRIVILEGES

출발 권한을 바꾸면, 평가하는 질문도 달라집니다.

시나리오를 선택하세요. 아래 질문은 실험 설계이며 아직 얻어진 결과가 아닙니다.

두 제품을 비교할 때 고정할 조건

데이터

동일한 합성 데이터·표식·질문을 사용. 정상적으로 데이터가 존재하고 조회 가능한지 대조 시험으로 확인합니다.

권한

동일한 위협 시나리오를 적용하되 제품별 실제 권한을 기록. DB 관리 권한에 앱·OS·키 접근 권한을 자동 포함하지 않습니다.

환경

버전·암호화 설정·키 저장 위치·캐시·로그·백업 범위·조회 시점·스냅샷을 기록합니다.

호스트 권한을 미리 제공한 시험은 해당 권한에서의 노출을 평가합니다. 초기 침투나 권한 상승에 성공한 증거로 사용하지 않습니다.
WORKFLOW / QUALITY GATES

실행 → 증거 → 검토 → 필요한 부분만 다시 실행.

각 단계를 누르면 통과 기준과 실패 시 경로가 나타납니다. 오른쪽 주황 선은 Reviewer의 보충 요청을 Planner로 돌려보내는 흐름입니다.

엔진 확장 제안

시험 결과와 실행 장애는 다른 상태입니다

준비→실행 중→검토 대기→검증됨

증거 부족

보충 필요 → Planner가 빠진 조건·증거에 대한 작업만 생성합니다.

모델 한도·연결 오류

대기 / 복구 필요 → 실행 이력과 완료된 도구 호출을 확인해 재개합니다. DB 보호 성공이나 시험 실패로 판정하지 않습니다.

범위 변경·반복 실패

Main에 판단 요청 → 종료·조건 조정·전문 검증을 선택합니다. 정해진 한도 없이 재실행하지 않습니다.

병렬로 실행해도 되는 작업

  • 서로 다른 복제 환경의 제품별·권한별 시험
  • 완료된 증거의 읽기 전용 검토
  • 다른 결과 묶음에 대한 보고서 초안 작성

순서와 잠금이 필요한 작업

  • 동일 DB의 설정·계정·데이터 변경
  • 한 호스트의 스냅샷 복원과 실행 중 시험
  • 결과에 영향을 주는 키·캐시·로그 상태 변경

외부 모델 호출

Codex CLI도 외부 모델을 호출합니다. “시험망 격리”와 “프롬프트·도구 결과의 외부 전송 제한”은 별도 설계 항목입니다. 자동 요약만으로 민감 정보 제거가 보장되지는 않습니다. 근거: NIST §7.4.

원본 증거 보존과 보고서

검증에 필요한 원본은 로컬에서 보존하고, 공유 보고서에는 필요한 최소 증거와 참조를 사용합니다. 실험 데이터의 수집·저장·전송·폐기 기준을 기록합니다.

비용도 실험 기록에 연결

작업·역할·모델·입출력 토큰·캐시 사용량·재시도 횟수를 연결합니다. API 환산 추정 비용, 실제 API 청구액, 구독 사용량 한도는 구분합니다.

현재 ARTEX와 제안의 차이

현재: Worker 종료 후 Planner를 깨우는 실행 루프, 결과·보고 기능이 있습니다.

추가 제안: 독립 Reviewer의 검토 대기열, 검증 상태, 보충 작업 연결, 검증에 기반한 목표 완료 게이트.

주의: 에이전트 이름을 추가하는 것만으로 이 흐름이 구현되지는 않습니다.

확인 지점: server/engine.go의 NotifyDone, server/orchestration.go의 Reporter 초기화. 이 보드는 실행 엔진을 변경하지 않습니다.
이번 보드에서 확정하지 않은 기본값

Worker 수, Reviewer 모델, 최대 보충 횟수, 비용·시간 상한, 제품 버전, 테스트 네트워크와 호스트 구성은 모두 미정입니다. 화면의 역할 수는 실제 동시 실행 수를 뜻하지 않습니다.

논의를 이어갈 때 보드가 바뀌는 방식

채팅에서 결정된 내용을 해당 화면에 반영하고, 제안·확정 표시와 변경 이력을 갱신합니다. 브라우저의 로컬 메모는 파일이나 대화와 자동 동기화되지 않습니다.

현재 Codex 브리지는 ARTEX의 모델 요청과 도구 호출을 연결합니다. Codex를 별도 코딩 작업자로만 제한할 이유는 없습니다. Main·Planner·Worker에 서로 다른 프로필을 붙이는 구조를 유지할 수 있습니다.

소스 분석이나 테스트 코드 작성도 필요한 작업으로 배정합니다. 해당 작업이 볼 수 있는 코드·자격·정답 정보는 시험 조건에 명시합니다.

로컬 근거: scripts/codex_probe/README.md의 호출 흐름. 이 화면은 새 모델 라우팅을 실행하거나 설정을 변경하지 않습니다.
VERIFICATION / 판정 책임 분리

프로그램이 확인하는 사실과 Reviewer의 해석

  • 로컬 검증기: 실행별 표식·수신 기록·대상 로그·내용 일치와 출처를 대조합니다.
  • Reviewer: 어떤 경계가 실제로 넘어갔는지, 관측이 보호 주장과 어떻게 연결되는지 해석합니다.
  • 완료 게이트: 필요한 증거와 검토가 채워졌는지 확인하고 예산·중단 상태를 별도로 기록합니다.

자동 검증의 판정 조건도 시험별로 정의해야 합니다. 정상 권한으로 읽은 데이터를 모두 “접근 통제 취약점”으로 분류하면 안 됩니다.

접근·노출·반출·통제 효과를 각각 기록합니다

평가 축직접 필요한 증거혼동하면 안 되는 결론
도달 가능지정 시작점의 실제 서비스 응답연결됨 ≠ 인증 우회됨
인증·권한 경계 위반시작 주체의 권한과 원래 불허된 접근의 성공제공된 관리자 계정의 정상 조회 ≠ 권한 위반
기밀 정보 노출표식의 출처·관측 위치·권한·데이터 처리 조건관측됨 ≠ 암호 알고리즘이 깨짐. 명시된 보호 범위와 비교 필요
반출 경계 통과별도 실험 수신 구역의 기록 + 실행별 데이터 대조 + 실제 획득 경로로컬 출력·모델 프롬프트 전송 ≠ 정의한 반출 시험 성공
탐지·차단 효과행동이 실제 수행됐다는 증거와 로그·경보·차단의 시간 연결도구 오류·모델 한도 ≠ 보안 통제의 차단 성공
평가 종료검증된 항목·미해결 항목·종료 이유예산 소진으로 종료 ≠ 모든 질문 검증 완료

위 평가 축과 판정 구성은 이번 프로젝트를 위한 설계 제안입니다. 공격 목표 달성 여부, 통제 효과, 증거 확실성을 별도 필드로 기록합니다.

검증용 정답이 실행 팀에 새지 않도록

실험별 합성 표식과 기준 데이터는 환경 준비·검증 측에서 관리합니다. 실행 팀이 정답이나 검증용 관리자 자격을 미리 받으면 대상 경로를 거치지 않고 성공처럼 보이는 결과를 만들 수 있습니다.

수신 표식 일치만 보는 대신 실행 ID·출처·읽기 경로·수신 기록을 연결합니다. 합성 표식 사용과 내부 수신 서버는 여전히 설계 가정입니다.

초기 진입이 막히면: leg-up

사전에 정한 기준에 따라 접근이나 정보를 제공하여 후속 목표를 시험할 수 있습니다. 제공 전후를 분리하고, 해당 지점까지 침투에 성공했다고 보고하지 않습니다.

우리 설계에서는 “실제로 획득한 접근”과 “시험을 위해 제공된 접근”을 서로 다른 기록으로 남깁니다. 초기부터 권한을 제공하는 노출 평가와, 진행 중 도움을 받는 leg-up도 구분합니다.
